# 02 · 核心、配置与版本契约

**目标：** 不凭协议名字推断兼容性。**前置：** 01。

## 配置解析只是第一关

引擎能读取配置，只说明字段被接受。入口还可能没有监听、证书不能验证、凭据不匹配、UDP 被过滤、转发被规则拦截。验收顺序应为：解析 → 启动与监听 → 正确身份转发 → 错误身份拒绝 → 重启恢复 → 版本切换与回滚。

本仓库固定 Mihomo **1.19.31** 的官方镜像摘要；1.19.30 作为回退实验基线。准确摘要见 `versions.lock.json`。锁的是多架构索引，本部署明确选 `linux/amd64`。更新标签不能覆盖这个约定。

## 版本矩阵必须有四个维度

| 维度 | 应记录内容 |
| --- | --- |
| 服务端 | 核心版本、镜像摘要、启用入口、TLS 材料版本 |
| 客户端 | 应用名与版本、实际核心版本、设备系统 |
| 配置 | 协议、传输、flow、SNI、拥塞控制和 UDP 模式 |
| 验证 | TCP/UDP 正负认证、证书验证、转发出口、生命周期 |

本地 Docker 核心之间互通，不代表任意版本的移动客户端都互通。Clash Mi 的未知版本仍待设备端测试；也不能用另一核心的 XHTTP 文档拼进 Mihomo 配置。

## 读代码与实验

`jp/config.py` 是字段的唯一生成入口。生成的 `.yaml` 使用 JSON 语法，因为 JSON 是 YAML 1.2 的子集，减少手写缩进错误。配置不含自写协议、密码算法或 TLS。

```bash
python3 scripts/manage.py local-test --state /tmp/relay-local-new --protocols reality hy2
```

这会启动独立、没有宿主发布端口的实验网络。测试目标与客户端不在同一网段，直连必须失败，避免把直连当成代理成功。请使用从未运行过的新状态目录。

## 检查点

如果 `-t` 成功、错误密码也能下载，能否验收？不能：可能客户端绕过节点、回落直连，或服务端认证没生效。每个可选入口都需要独立负例。
