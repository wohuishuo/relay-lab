# 13 · 案例：为什么下载 1 Mbps，上传却很快

**目标：** 用证据约束结论，再选择下一项实验。**前置：** 03、05–08。

## 观察不是结论

用户提供的单张测速截图，单位均为 Mbps：

| 截图标签 | 下载 | 上传 |
| --- | ---: | ---: |
| gRPC / WS VLESS XUDP / AnyTLS（合并标签） | 1.34 | 179 |
| XHTTP VLESS XUDP | 1.61 | 23.6 |
| Trojan | 1.40 | 125 |
| TUIC | 121 | 179 |
| Hysteria2 | 84.7 | 368 |
| REALITY VLESS XUDP | 1.96 | 120 |

合并标签不能拆成三次独立测量。截图没有测试目标、并发数、时间、设备负载、客户端核心版本等信息。可以观察到外层 TCP 类入口下载偏低、两个 QUIC 入口较高；**不能由此证明某个配置冲突或特定网络策略是根因**。

## 把解释写成可证伪的假设

| 假设 | 支持它需要什么 | 如何区分 |
| --- | --- | --- |
| TCP 方向性整形或路径损伤 | 同目标同时段 TCP 下行异常，其他条件一致 | 换接入网、方向测试、未来抓包 |
| TCP 拥塞/窗口受限 | 重传、RTT、发送窗口、接收窗口证据 | 单流与多流、不同 RTT 对照 |
| 核心 CPU/内存受限 | 慢时 CPU 饱和、节流或 OOM | 同时采集资源趋势 |
| 路径/端口策略 | 换端口或协议后差异稳定 | 维护窗口一次只改一项 |
| HTTP 包装/流控开销 | 特定传输的请求/流控停顿 | 同一目标的长短流、并发对照 |
| 测速服务偏差 | 不同节点被分配不同测试服务器 | 固定测试端点与文件 |
| MTU/PMTU 黑洞 | 小包通、大包卡，报文/重传线索 | 有边界的包长扫描 |

这些解释可以同时存在。CPU 瓶颈通常不会仅凭“内存 14%”就被排除；单核某线程占满与全机平均值不同。一个端口冲突更常表现为绑定失败，而不是自动制造稳定的 1 Mbps 限速。

## 本机完成了什么实验

两个隔离 Docker 网络，只有服务端连接两边。Mihomo 官方固定镜像处理全部代理协议；受控 HTTP 目标返回带 SHA256 校验的数据。每个协议双向各 3 次、每次 2 MiB，失败单独计数，顺序交替。

**实验 A：无损虚拟网络。** 九种入口全部双向成功，没有共同的约 1 Mbps 下载限制。它说明该生成配置没有在此环境稳定复现同样瓶颈；不能排除特定生产客户端、真实路径或部署差异。短流虚拟网络的 Gbps 数字不是 VPS 公网带宽。

**实验 B：额外双向各 40 ms 延迟与单向损伤。** 下表为下载/上传中位数 Mbps，每格各 3 个样本：

| 场景 | REALITY | HY2 | TUIC | SS |
| --- | ---: | ---: | ---: | ---: |
| 仅额外约 80 ms RTT | 13.27 / 10.94 | 18.06 / 22.63 | 14.35 / 22.64 | 16.00 / 15.26 |
| 服务端出口额外 1% 随机丢包 | 10.22 / 12.50 | 22.95 / 24.45 | 23.95 / 29.64 | 9.92 / 16.67 |
| 客户端出口额外 1% 随机丢包 | 7.71 / 3.45 | 23.07 / 22.45 | 8.77 / 23.10 | 6.22 / 3.39 |
| 服务端出口 2 Mbps 限速 | 1.83 / 16.95 | 1.85 / 26.91 | 1.86 / 24.31 | 1.85 / 19.69 |

实验 B 的 96 次传输均完成并通过载荷校验。最后一行证明单向限速可以制造“下载很慢、上传快”；且它影响所有协议，所以**不能用这个实验直接解释截图里仅 TCP 受限的差异**。

丢包实验里个别 QUIC 样本反而比仅延迟更快，这提醒我们 3 次短流不足以做性能显著性结论。随机丢包未固定种子，Docker VM 调度与分段卸载也会影响模型。记录的 qdisc 计数在测试前采集，仅证明规则已安装，不能冒充实际丢包统计。

完整原始样本见 [directional.json](../../reports/directional.json)、[baseline.json](../../reports/baseline.json)。性能不是“通过/失败”排名：报告 passed 表示传输与校验通过。

## 可以优化吗

可以设计优化实验，但必须先定位瓶颈。候选包括选择适合接入网的传输、调整有证据支持的 MTU/窗口/拥塞参数、减少不必要包装、迁移不同线路或增加独立节点。若共同瓶颈是 2 Mbps 限速，再改密码、加密方法或健康检查都无效。

本轮没有在生产启用 BBR、改 sysctl、换端口、重启或跑压测。下一步应在维护窗口先收集短时只读指标，再提出带撤回条件的单变量实验。继续：[测量方法](14-measurement.md)。
